OpenEmu-Silicon. O aplicativo continua com `macOS Deployment Target = 26.0`,
pois esta é a versão mínima realmente testada neste projeto.

## Uso no empacotamento

Depois de gerar um archive Release, o fluxo pode usar os pacotes baixados assim:

```bash
UPDATED_CORE_BUNDLE_DIR="$HOME/Downloads/OpenEmu-Cores-v1.6.0" \
    ./Scripts/bundle-all-cores.sh \
    "/caminho/para/OpenEmu.xcarchive"
```

Os arquivos ZIP não são versionados no repositório. Antes da publicação, cada
bundle deve ser colocado nos assets da release do projeto e ter seu appcast
correspondente atualizado e assinado.

## Verificações realizadas

- `MARKETING_VERSION`: `2.2.0`.
- `CURRENT_PROJECT_VERSION`: `28`.
- `CFBundleShortVersionString`: `2.2.0`.
- Alvo macOS: `26.0`.
- Bundles baixados: ZIP íntegro, arm64 e assinatura local verificável.
- Build Xcode do target `OpenEmu`: concluído sem erros.
- Scripts de empacotamento: sintaxe Bash validada.
- `Scripts/verify.sh`: a etapa oficial não pôde executar o build porque o
  `xcodebuild` desta máquina não reconheceu o pacote
  `OpenEmu-metal.xcworkspace`; a validação equivalente pelo BuildProject do
  Xcode passou. A limpeza automática do script também encontrou restrições de
  permissão no DerivedData do usuário.
- Testes do esquema `OpenEmu`: 7 de 7 passaram. `ImportFailureTests` agora
  isola os sistemas habilitados no próprio teste, evitando que preferências
  persistentes da biblioteca alterem a expectativa do arquivo compactado.
